# 飞书知识库（原始资料）内容说明

状态：Draft
日期：2026-10-20
最近修订：2026-10-22（统一知识库称呼）
简称：原始库

本文档说明飞书知识库（原始资料）中应该包含哪些目录、文档，以及每份文档写什么。它只定义内容范围，
不包含示例知识。

字段模型、同步机制和检索流程见 `docs/architecture.md`。

## 1. 定位

- 原始库由用户维护，插件只读取，不写入。
- 原始库是一个飞书知识库（Wiki 空间），内容以文档节点存在，每个节点对应一份 docx 文档。
- 原始库保存可长期复用的知识：通用方法加项目设定。
- 原始库不保存剧本、不保存生成结果、不保存插件运行状态。
- 每个 Wiki 文档是一个独立同步单元，修改后由同步人员运行 `knowledge-sync` 重新归纳成知识卡。

## 2. 目录结构

```text
通用知识/
  拆镜方法/
  分镜知识/
  提示词技巧/
  Seedance/

项目知识/
  <project_id>/
    项目概述/
    角色圣经/
    场景说明/
    视觉风格/
    项目术语/
```

路径决定知识范围：

| 路径 | 推导结果 |
| --- | --- |
| `通用知识/...` | `scope=general` |
| `项目知识/<project_id>/...` | `scope=project`、`project_id=<project_id>` |

`project_id` 必须稳定，改名等于换项目。目录放错会导致知识在检索时被项目过滤掉。

## 3. 通用知识

适用于所有项目。每份文档只讲一个主题，便于同步时独立更新。

| 目录 | 应包含的文档 | 内容 |
| --- | --- | --- |
| `拆镜方法/` | 剧本解析方法 | 剧本拆成集、场景、节拍、动作单元、情绪单元、对白单元的规则；对白转视觉动作；原文边界与缺失信息处理方式 |
| `分镜知识/` | 镜头语言词典 | 景别、机位与角度、运镜、焦段、景深、构图、光线和色彩的术语与使用场景 |
| `分镜知识/` | 镜头组与组接 | 镜头组划分、镜序、转场、节奏与时长控制、连续性检查 |
| `提示词技巧/` | 提示词结构 | 主体、动作、环境、镜头、光线、色彩、风格、约束的写法；也可承载模型限定的提示词工艺卡（例如 Seedance 2.5 专属的台词、声音、阶段化写法），仍归 `prompt_technique` |
| `提示词技巧/` | 正例反例 | 可对照的正例和反例，写明改了什么、为什么更好 |
| `提示词技巧/` | 常见错误 | 常见错误清单与修正方法 |
| `Seedance/` | 模型使用经验 | Seedance 2.0 与 2.5 的软知识：能力差异、时长与拆分经验、参考素材写法、多语言台词和多视图参考的注意事项；该目录承载 Seedance 软知识与 `seedance_rule` 卡（例如负面约束策略） |

约束：

- 一份文档只覆盖一个主题，主题变大时拆成多份，不无限追加。
- 术语只用一种写法，全文一致。
- 目录与分类冲突时以卡片 `category` 优先：目录只做文档组织，知识卡按
  `card-authoring.md` 的分类映射归类。`prompt_technique` 卡（含模型限定的提示词
  工艺卡）放 `提示词技巧/`，`seedance_rule` 卡与 Seedance 软知识放 `Seedance/`；
  模型专属性由卡片 `target_models` 表达，不用目录区分。
- 外部事实（模型能力、官方限制）必须标注来源和检索日期。
- 硬规则不写进原始库：时长上限、画幅、必填字段和禁止项由 `rules/models/*.json` 负责。

## 4. 项目知识

每个项目一套，放在 `项目知识/<project_id>/` 下。跨集稳定设定来自这里，临时状态不进这里。

| 目录 | 应包含的文档 | 内容 |
| --- | --- | --- |
| `项目概述/` | 项目概述 | 一句话简介、类型定位、目标受众、整体基调、创作边界（必须做到、可以有条件使用、禁止出现） |
| `角色圣经/` | 角色总表 | 角色索引：主称谓、别名、定位、首次出场 |
| `角色圣经/` | 角色档案 | 每个主要角色的基本档案、外观、服装、动作习惯和状态表 |
| `场景说明/` | 场景总表 | 场景索引：主称谓、别名、室内外、主要时段、首次出场 |
| `场景说明/` | 场景档案 | 每个主要场景的定位、空间布局、材质与色彩、家具陈设、出入口、可识别地标、时间与天气、场景状态表 |
| `视觉风格/` | 视觉风格 | 风格总述、参考来源（写明参考什么、不参考什么）、色彩规范、光线规范、镜头语言偏好、画面质感、禁止风格与可复用的约束短句 |
| `项目术语/` | 术语与命名 | 项目内固定叫法、命名规则、专有名词表、易混名称对照 |

写作要求：

- 只写可执行的可见信息，例如伤疤的位置和长度可以写，抽象的气质评价不可以写。
- 状态表只记录与基准不同的部分，不重复常态。
- 只写图鉴式设定，不写剧情：剧情、台词和结局不进入项目知识。
- 不出现真实明星、真实品牌和受版权保护的知名形象，需要时改写为虚构名称。

## 5. 维护约定

- 原始库由用户维护，插件和 MCP Tool 只读。
- 修改原始库后必须在约定的同步窗口运行 `knowledge-sync`，否则 AI 库和本地索引不会更新。
- 新增、修改、移动和删除文档都会被同步处理；删除文档时，对应知识卡和 `SyncState` 记录一并清理。
- 新增项目时先建 `项目知识/<project_id>/` 目录结构，再补内容。

## 6. 起步建议

先建最小集合：通用知识的四类各一份，项目知识的五类各一份，项目概述和角色圣经优先。

其余文档按实际需要增补，不追求一次写全。

## 7. 链接占位文档（2026-10-22）

Wiki 文档的正文可以只是一条外部引用（「链接占位」），知识正文放在引用目标里。
同步时会先展开引用、读取目标全文，再和文档正文一起归纳成知识卡。支持两种形态：

| 形态 | 原始库中的写法 | 同步时的读取方式 |
| --- | --- | --- |
| 飞书云文档 | 插入文档引用卡片，或写 `/docx/<token>`、`/wiki/<token>` 链接 | lark-cli 直接读取（确定性） |
| 网页 | 写 `http(s)://` 链接 | 服务端 HTTP 读取并转纯文本 |

使用要求：

- 优先使用飞书云文档引用：它由 lark-cli 读取，稳定且能记录 revision。
- 网页链接要求目标页在静态 HTML 里就带正文。JS 渲染的页面（例如很多文档站的 SPA）
  取不到正文，同步会返回 `needs_render` 并由执行同步的会话用浏览器工具读取；如果
  没有可用的浏览器通道，请把内容复制进 Wiki 文档后再同步。
- 引用只展开一层。引用文档内部还有引用时，需要把内容并入当前 Wiki 文档。
- 同步读到的引用内容必须在知识卡里写明来源（token 或 URL）与检索日期。
- 引用目标变化不会改变 Wiki 节点的编辑时间，因此不会自动触发重同步；更新后用
  「只同步这个文档」的指定文档模式刷新。
